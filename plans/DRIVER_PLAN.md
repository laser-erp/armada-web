## Распознавание документов (модель каршеринга)

**Эталон:** онбординг в [Делимобиль](https://delimobil.ru), [Яндекс Драйв](https://yandex.ru/support2/drive/ru/joining/how-to-join), [BelkaCar](https://belkacar.ru) — водитель **не вводит поля руками**, а **фотографирует документы в приложении**; система сама извлекает реквизиты и подставляет их в профиль и заявки.

### Как это устроено у каршеринга (типовой сценарий)

1. **Телефон и вход** — SMS/PIN, привязка к аккаунту (у нас уже есть invite + PIN).
2. **Съёмка с подсказками UI** — рамка в камере, требования «без бликов», «все углы в кадре», «оригинал, не скан из экрана» ([Яндекс Драйв — требования к документам](https://yandex.ru/support2/drive/ru/joining/required-documents)).
3. **Набор кадров:**
   - паспорт РФ: разворот с фото;
   - паспорт: страница с регистрацией;
   - водительское удостоверение: лицевая и оборотная стороны;
   - **селфи с паспортом** (лицо + разворот в руках) — антифрод и сверка «за рулём тот же человек» ([Делимобиль FAQ](https://promokod-delimobil.su/faq.html)).
4. **OCR / IDP на бэкенде** — нейросеть определяет тип документа и извлекает поля (ФИО, серия/номер паспорта, кем/когда выдан, номер и срок ВУ, категории). Используется связка **OCR + Intelligent Document Processing** (предобработка кадра, выпрямление, нормализация полей). Примеры поставщиков для РФ: [Dbrain](https://dbrain.io/proverka_voditeley), [Beorg](https://beorg.ru), [Базис.Документы](https://doc.basis.center/), [IDX](https://iidx.ru).
5. **Проверка (KYC)** — поверх OCR:
   - **Liveness** — живой человек, не фото/маска;
   - **сверка селфи с фото в паспорте**;
   - опционально — сверка ВУ с реестрами / проверка срока действия / антифрод по подделкам;
   - ручная модерация службой безопасности при низкой уверенности OCR (15 мин – 24 ч у каршеринга).
6. **Автозаполнение профиля** — извлечённые поля попадают в карточку водителя; диспетчер только подтверждает или правит расхождения.
7. **СТС авто** (для перевозчика, не клиента каршеринга) — тот же пайплайн: фото СТС → серия/номер + при необходимости привязка к госномеру в парке ([Базис.Документы — СТС, ПТС](https://doc.basis.center/)).

### Целевой сценарий в АРМАДА

| Шаг | Статус | Комментарий |
|-----|--------|-------------|
| Камера в `/v` → «Добавить документы» с рамкой и подсказками | ⬜ | UX как в каршеринге |
| Загрузка набора: паспорт (2 разворота) + ВУ (2 стороны) + селфи | ⬜ | Можно начать без liveness |
| OCR API → поля `passportSeries`, `passportNumber`, `licenseNo`, … | ⬜ | MVP: один провайдер (Dbrain / Beorg / Базис) |
| Предпросмотр: водитель правит поля с низкой confidence | ⬜ | Показать % уверенности по полю |
| Отправка на модерацию диспетчеру или автопринятие при score > порога | ⬜ | Уведомление в `/a` |
| Снимки в профиле водителя и ТС, копия в заявку при назначении | ✅ | `passportPhoto*`, `licensePhoto*`, `stsPhoto` |
| Liveness + сверка лица с паспортом | ⬜ | Этап 2, как у каршеринга |
| Скан СТС в карточке ТС через тот же OCR | ⬜ | Связать с `stsSeries` / `stsNumber` |
| Офлайн: сохранить кадры локально, OCR при появлении сети | ⬜ | Аналог офлайн-смены |

### Технические ориентиры интеграции

- **Формат:** REST API, `multipart` или base64 JPEG/WebP; ответ JSON с полями и `confidence`.
- **Документы РФ:** паспорт (10/11 цифр), ВУ (новый/старого образца), СТС.
- **Безопасность:** не хранить сырой селфи дольше срока проверки; шифрование at-rest; согласие на обработку ПДн в онбординге.
- **Fallback:** если OCR недоступен — ручной ввод диспетчером (текущее поведение).
