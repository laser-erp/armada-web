## 1. Что на armada.sx и что уже в приложении

По публичным данным сайта (услуги, meta, prices):

| Направление на сайте | Есть в ATI/приложении | Комментарий |
|----------------------|------------------------|-------------|
| Аренда **шаланды** | ✅ `shalanda` | Флагман услуги (арендашаланды.рф) |

**Вывод:** для «грузовых кузовов» база **61 типа ATI** уже скачана и частично подключена. Для полного соответствия armada.sx нужен **второй слой — «строительная/спецтехника»** (аренда по часам/смене, не км-тариф).

| Компонент | Сейчас | Проблема |

## 2. Целевая модель

### 2.1 Единый справочник `vehicleTypes`

Один JSON (уже есть `data/ati-body-types.json`) + расширение для Армады:

```text
vehicleTypes/
  id              — slug (manipulator, shalanda, …)
  label           — «манипулятор»
  category        — closed | refrigerated | open | specialized | equipment
  atiTypeId       — связь с ATI (nullable для экскаватора)
  armadaFeatured  — показывать на первом экране (шаланда, манипулятор, …)
  defaults        — типовые ограничения (см. §3)
```

Генерация `ATI_BODY_TYPES` в `store.js` — **из JSON**, не дублировать массив вручную.

### 2.2 Настройки по типу (на фирму)

Хранить в `finance.vehicleTypes[typeId]` (per company):

| Поле | Для чего | Пример: манипулятор |
|------|----------|---------------------|
| `enabled` | Фирма возит этим типом | true |
| `priceMult` | Надбавка к расчёту | ×1.4 |
| `ratePerHour` | Перекрывает общий ₽/ч | 2500 |
| `ratePerKm` | Перекрывает ₽/км | null |
| `minWorkHours` | Мин. смена | 4 |
| `podachaHours` | Подача | 2 |
| `podachaFee` | Фикс. выезд | 5000 |
| `heavyTonsFrom` / `heavyMult` | Тяжёлый груз | 20 / ×1.15 |
| `allowedLoadMethods` | top, rear, crane, … | rear, ramps |
| `allowedCargoKinds` | food, bulk, … | general |
| `requiresTemp` | Реф/изотерм | false |
| `minLengthM` / `minWidthM` / `minHeightM` | Дефолт для заявки | — |
| `maxPayloadTons` | Дефолт грузоподъёмности | 10 |
| `exchangePublish` | Показывать на бирже | true |
| `pricingMode` | `km` \| `hour` \| `trip` \| `request` | hour |
| `notes` | Подсказка диспетчеру | «КМУ до 7 т» |

**Наследование:** если для типа нет записи — брать категорию (`specialized` → ×1.2), затем общий тариф фирмы.

### 2.3 Парк

В `normalizeFleetVehicle` добавить:

- `bodyTypeIds[]` — один или несколько типов (тягач + полуприцеп)
- `bodyTypePrimary` — основной для матчинга
- `equipmentExtras` — для манипулятора: `craneTons`, `boomReachM`

### 2.4 Заявка

- `reqBodyType` → хранить **полный id** (`manipulator`, не `board`)
- `reqBodyTypes[]` — если заказчик выбрал несколько (как сейчас в UI)
- `pricingBodyType` — id для калькулятора (primary)

## 6. Миграция и риски

| Риск | Решение |
|------|---------|
| Старые заявки с `reqBodyType=board` | Маппинг id → id при загрузке; `mapTo` deprecated |
| Слишком сложный тариф для малых парков | Preset «как сейчас» (4 группы) + раскрыть детали |
| 61 строка в тарифах | UI по категориям + поиск; bulk edit категории |
| PocketBase payload size | Хранить только overrides (enabled + mult), не полный объект |
| Спецтехника ≠ ATI | Отдельный enum, не ломать ATI-совместимость биржи |

---

## 7. Критерии готовности (MVP)

1. Заказчик выбирает **любой** из 61 типа; в заявке сохраняется точный id.
2. У каждой машины в парке указан тип; подбор учитывает тип.
3. В тарифах фирмы для **минимум 6 типов Армады** (шаланда, манипулятор, тент, самосвал, трал, реф) — **свои** множители или ₽/ч.
4. Минимальная цена в портале отражает тип (манипулятор дороже тента).
5. Документы и биржа показывают «манипулятор», а не «бортовой».
