# План: доработка лендингов АРМАДА

**Статус:** согласование · **не в коде** (31.08.2026)  
**Сравнение:** [CARGO.RUN](https://cargorun.ru/) — enterprise-TMS; **АРМАДА** — сеть кабинетов для парка 1–15 машин и партнёров.  
**Файлы:** `landing.html`, `kp-logist.html`, `kp.html`, `kp-zakaz.html`, `landing.css`, входы `/a` `/v` `/z` в `index.html`

---

## 1. Цель

Повысить **конверсию в пилот / вход** без превращения сайта в «мини-CARGO.RUN»:

- человек за **10 секунд** понимает роль и выгоду;
- видит **продукт глазами** (скрины, не только текст);
- доверяет (**реальные цифры**, контакты, честное «чем мы не TMS»);
- может **оставить заявку** или **войти** без тупика.

**Не делаем в этом плане:** топливный модуль, интеграции 1С/SAP, App Store, мультиязычность, SEO-журнал на 50 статей.

---

## 2. Принципы (отличие от CARGO.RUN)

| CARGO.RUN | АРМАДА — оставляем и усиливаем |
|-----------|--------------------------------|
| Парк 50–400+ ТС | **1–15 машин**, владелец часто за рулём |
| TMS + GPS + fuel | **Кабинет + биржа партнёров + портал заказчика** |
| Внедрение под ключ, презентация | **Пилот 30 дней**, вход по ссылке/PIN |
| Нативные приложения | **Веб + SMS**, без установки |
| ATI / открытые доски | **Закрытая сеть кабинетов**, не клон ATI |

**Тон:** простой, «свой человек в логистике», не корпоративный английский на главной.

## 4. Этапы работ (порядок)

### Этап L1 — «Понял за 10 секунд» · приоритет **высокий**

**Задача:** дожать тексты и структуру без тяжёлой графики.

| # | Что | Где | Детали |
|---|-----|-----|--------|
| L1.1 | Единый **hero** по шаблону | все `kp-*.html` | Подзаголовок: *кому* + *главная боль* + *одна цифра* (напр. «−70% звонков») |
| L1.2 | Блок **«Не ATI и не CARGO.RUN»** | `kp-logist.html`, `kp.html` | Таблица 3 колонки: ATI · крупная TMS · АРМАДА |
| L1.3 | **Sticky CTA** внизу на мобиле | `landing.css` | Полоска: «Пилот» / «Войти» — не теряется при скролле |
| L1.4 | Контакты в footer | все лендинги | Телефон + Telegram (решение ниже) + email; не только Gmail |
| L1.5 | Meta / Open Graph | `<head>` всех лендингов | `og:title`, `og:description`, превью-картинка 1200×630 |
| L1.6 | Хаб `landing.html` | первый экран | Одна строка УТП: «Сеть кабинетов — не доска объявлений» |

**Критерий готовности:** новый человек с телефона за 10 с понимает роль и следующий шаг (войти / пилот / почитать).

---

### Этап L2 — «Вижу продукт» · приоритет **высокий**

**Задача:** закрыть главный разрыв с CARGO.RUN — нет скринов.

| # | Что | Где | Детали |
|---|-----|-----|--------|
| L2.1 | **4 скрина** (PNG/WebP) | `web-preview/landing/` | ① список заявок логиста ② биржа «Забрать» ③ экран водителя (смена/заказ) ④ портал заказчика |
| L2.2 | Секция **«Как это выглядит»** | `kp-logist.html` (эталон), остальные — по 2 скрина | Карусель или сетка 2×2; подпись под каждым |
| L2.3 | **Mockup** на hero (опционально) | `landing.css` | Телефон в рамке + один скрин — без тяжёлого JS |
| L2.4 | Скрины на **входах** `/a` `/v` `/z` | `index.html` + `entry.css` | Мини-превью слева от формы (desktop) или под заголовком (mobile) |

**Подготовка:** снять с prod `app.armada.sx` (демо-данные) или собрать статичный mockup в Figma — **решение D1**.

**Критерий:** на лендинге логиста минимум 3 изображения интерфейса с подписями.

## 6. Дизайн и техника

| Тема | Решение |
|------|---------|
| Стили | Расширять `landing.css`, не плодить CSS на каждой странице |
| Картинки | `web-preview/landing/*.webp`, width ≤ 960, lazy-load |
| JS | Минимум: карусель на чистом CSS или 20 строк; формы — HTML5 |
| Доступность | `alt` у скринов, контраст кнопок, focus-visible |
| Mobile-first | Sticky CTA, скрины вертикально, таблицы → карточки |
| Кэш | `?v=APP_BUILD` при деплое |

## 8. Метрики успеха (после L1–L2)

| Метрика | Как мерить |
|---------|------------|
| Клик «Войти» / «Пилот» | Яндекс.Метрика или простой счётчик (опционально) |
| Время на странице | Метрика |
| Заявки на пилот | Кол-во писем / форм в неделю |
| Отказ «не понял что это» | Обратная связь с первых 5 пилотов |

**Цель первого месяца после L1–L2:** ≥ 3 заявки на пилот с лендинга без объяснений в переписке «а что вы вообще делаете».

## 9. Оценка объёма (техническая, не календарная)

| Этап | Файлы | Инвазивность |
|------|-------|--------------|
| L1 | 5 HTML + `landing.css` + `entry.css` | Низкая — тексты и CSS |
| L2 | + папка `landing/`, правки 4 HTML | Средняя — нужны ассеты |
| L3 | тексты + возможно 1 новая секция | Низкая — нужны данные от вас |
| L4 | формы + `landing-thanks.html` | Средняя — зависит от D5 |
| L5 | +2 HTML | Низкая |

**Рекомендуемый порядок внедрения в код:** L1 → L2 → L3 → L4 → L5.  
После каждого этапа — деплой и просмотр с телефона.
