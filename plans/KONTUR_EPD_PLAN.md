## Разделение: платформа vs кабинет клиента

| Что | Супер-админ (Армада) | Логист (любой кабинет с тарифом ЭТrН) |
|-----|----------------------|----------------------------------------|
| Ключ разработчика Контура | ✅ только на VPS (`armada-api/.env`) | ❌ |
| Письма **оператору Контура** (API, ключи, sandbox) | ✅ `operator-letters.js` | ❌ |
| Журнал API / webhook платформы | ✅ Активность → ЭПД | ❌ |
| **boxId** своей организации | ✅ вводит супер-админ | 👁 «подключено» / «ждём» |
| Подпись T1–T4 по заявкам | ✅ | ✅ |
| Шаблоны писем **оператору подписи** (выпуск КЭП/ПЭП) | ✅ эталон | ✅ на **бланке клиента** |
| Фирменный бланк, логотип | свой кабинет | ✅ только **их** реквизиты; внизу мелко «Сформировано в сервисе Армада» |

**Платформенные настройки Контура для клиента** = модуль ЭТrН включён в тарифе + привязка **их** юрлица (boxId) + подписи + обмен титулами через сервер Армады (один ключ разработчика, маршрутизация по `spaceId`).

## UI: заказы (основное место)

### Список заказов
- Компактный **бейдж ЭТrН** на строке: `нет` · `T1 ждёт заказчика` · **`T2 — ваша подпись`** · `T3/T4 — водитель` · `закрыт ✓`
- Фильтр **«Нужна моя подпись»** (T2 для перевозчика)
- Фильтры: ждёт заказчика / ждёт водителя

### Карточка заказа
- Блок **ЭТrН**: лента титулов, кто подписал, кнопка «Подписать», QR, печать, ссылка на T1

### Настройки (редко)
- Статус Контура (подключено / ждём boxId)
- Шаблоны писем оператору **подписи** (редактирование, печать/PDF)
- Карточки оформления подписи в профилях ролей

## Этапы реализации

### Этап 1 — Заказы + бланки + шаблоны писем *(готово в коде, 2026-09-02)*

1. Бейджи ЭТrН и фильтр «нужна моя подпись» в списке заказов.
2. Улучшить блок ЭТrН в карточке заказа.
3. **Шаблоны писем оператору подписи** — редактирование, печать/PDF на бланке **клиента** (логотип + реквизиты «нашей фирмы»).
4. Письма «Армада → Контур» — **только супер-админ** (убрать из клиентских кабинетов).
5. Бланк: шапка = клиент; footer = «Сформировано в сервисе Армада».

**Критерий:** логист видит в списке, где нужна его подпись T2; может распечатать письмо на подключение подписи на своём бланке.

---

### Этап 2 — Multi-tenant на сервере

- Один `KONTUR_CLIENT_ID/SECRET` на платформу; у каждого `space` — свой `boxId` / ИНН в `state.epdBySpace[spaceId]`.
- API: `GET/PUT /epd/space/:spaceId`; `POST /orders/:id/etrn` маршрутизирует по `order.spaceId`.
- Webhook обновляет титулы с привязкой к space.
- ЭТrН для любого кабинета с `billing.spaces[id].etrnEnabled`.

**Критерий:** smoke — ЭТrН заказа пилота уходит в **его** ящик (sandbox).

---

### Этап 3 — Подписи T1–T4 «из коробки»

- `POST /epd/sign-up-url`, `/epd/titul-sign-url`, `/epd/sign-status` на armada-api.
- Заказчик T1 (`/z`), логист T2 (профиль), водитель T3/T4 (приложение).
- Sandbox → бой. Пилоты: Нечаев, МБН; далее — новые клиенты с тарифом Business+.

**Критерий:** полный цикл T1→T4 на тестовой заявке (sandbox), затем один боевой рейс на проде.

---

### Этап 4 — T5–T8

*(После успешного T1–T4 на проде — см. решения выше.)*

- Переадресация, смена водителя/ТС, стоимость, эстафета.
- Те же бейджи в списке заказов + лента в карточке.

---

### Этап 5 — ЭДО договоров с контрагентами

- Рамочный договор: PDF + бумага + ЭДО (LOGIST_CABINET_PLAN §4.4, этапы 6a–6c).
- Статус подписания в карточке партнёра.
- Обмен через оператора (после печатных MVP).

---

### Этап 6 — Масштаб и бой

- `EPD_SANDBOX=false`, боевые boxId для клиентов.
- Help для логистов; ЭТrН по умолчанию в тарифе Business для новых space.

## VPS / armada-api (когда придут ключи)

Файл: `/opt/armada-api/.env` · шаблон: `scripts/armada-api.env.example`

1. Ключ разработчика — **один на платформу**.
2. **boxId** — per space, в state + админка супер-админа.
3. `EPD_SANDBOX=true` для теста.
4. `systemctl restart armada-api` → `/health` → `configured: true`.
